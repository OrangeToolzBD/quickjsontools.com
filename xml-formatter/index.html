XML Formatter

An XML formatter re-indents XML so every element starts on its own line, one level deeper than its parent. Paste XML, pick 2 spaces, 4 spaces or tabs, and press Format, or press Minify to strip the whitespace between tags. It also checks that each closing tag matches, following XML 1.0 (Fifth Edition, 2008), in your browser.

Updated September 20, 2026 · By Quick JSON Tools

How do I format XML?

Paste the XML and press Format. Each start tag, end tag, comment, CDATA section, processing instruction and DOCTYPE goes on its own line, indented by depth. An element that holds only text stays on one line, so <b x="1">t</b> is not split into three.

The tool’s test case:

<a><b x="1">t</b><c/></a>

<a>
  <b x="1">t</b>
  <c/>
</a>

Self-closing tags such as <c/> are kept as they are, and attributes are left untouched. Minify does the reverse: it removes the whitespace-only text between tags and joins everything onto one line.

Formatting changes whitespace, and in some XML that matters. When an element mixes text and child elements, the formatter puts each piece on its own line:

<p>Hello <b>world</b> again</p>

<p>
  Hello
  <b>world</b>
  again
</p>

For a document where spacing is meaningful, such as one marked xml:space="preserve" (which the XML specification uses to signal that whitespace should be kept), read the formatted copy but keep the original file.

Why does my XML fail to format?

The formatter stops when tags do not pair up. You will see “Closing tag </x> does not match an open tag” when an end tag closes the wrong element, and “Unclosed tag <x>” when an element is never closed. The usual causes are a typo, mismatched letter case or a missing end tag.

InputResult
<a><b></a>Closing tag </a> does not match an open tag
<a><b>Unclosed tag <b>
<Note></note>Closing tag </note> does not match (names are case-sensitive)
<a>1 < 2</a>Fails with an unclear error: escape the < as &lt;

The W3C specification treats names as case-sensitive and says a literal & or < may appear only as markup, so in text you must write &amp; and &lt;. This formatter stops with a clear message on both: <a>AT&T</a> is rejected until the ampersand is written as &amp;.

<company>AT&amp;T</company>
<rule>1 &lt; 2</rule>
<code><![CDATA[if (a < b && c) {}]]></code>

A CDATA section, as in the last line, lets you include code without escaping each character.

XML formatting vs validation

Formatting only changes layout. Validation checks rules. XML 1.0 separates two levels: a well-formed document follows the syntax rules, including a single root element and properly nested tags, while a valid document also has a document type declaration and obeys it. This tool checks tag syntax, nesting, bare & and < in text, and that there is a single root element, so it catches the common well-formedness errors, but it is not a full parser and not a validator.

What the formatter does not check: attribute quoting and duplicate attributes, character validity, or any DTD or XML Schema. For a real well-formedness check in a browser, the built-in XML parser reports errors:

const doc = new DOMParser().parseFromString(text, "application/xml");
const err = doc.querySelector("parsererror");
console.log(err ? err.textContent : "well-formed");

Checking against a schema needs a validating parser with the schema file. If your data started life as JSON, the JSON to XML converter produces nested elements you can paste here, and the diff checker compares two formatted versions line by line.

Frequently asked questions

How can I format an XML file?

Open the file in a text editor, copy the contents, paste them above and press Format. Choose the indent you prefer, then Copy the result back into the file. The formatting happens in your browser, so the file is not uploaded.

How do I convert XML into a readable format?

Indent it so each element sits on its own line under its parent; that is what the Format button does. If the XML came minified from an API or log, formatting is usually enough to read it. For very large files, a code editor with XML folding is easier to navigate.

Does formatting change my XML data?

It changes only whitespace between and around elements. Tag names, attributes and text are kept, but text inside elements that also contain child elements is trimmed and moved onto separate lines. That matters only where whitespace is significant, so keep the original for such documents.
