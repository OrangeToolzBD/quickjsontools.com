JSON Schema Generator

To go from JSON to schema, paste a sample document and press Generate schema. The tool writes a draft 2020-12 JSON Schema that records each value’s type, describes nested objects and arrays, and lists every key in the sample as required. Treat it as a starting point to refine, not a finished contract.

How do I create a JSON Schema from JSON?

Paste a representative JSON document and press Generate schema. The tool walks the sample and, for each value, writes its type: object, array, string, integer, number, boolean or null. Objects get properties and a required list, and arrays get an items schema built from their contents.

Worked example from the tool’s tests:

{"id": 1, "name": "x", "tags": ["a"], "meta": {"ok": true}}

produces

{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "id": { "type": "integer" },
    "name": { "type": "string" },
    "tags": { "type": "array", "items": { "type": "string" } },
    "meta": {
      "type": "object",
      "properties": { "ok": { "type": "boolean" } },
      "required": ["ok"]
    }
  },
  "required": ["id", "name", "tags", "meta"]
}

(Output shown here in compact form; the tool indents every level.) A single sample cannot show everything, so review these points before using the schema:

  • Whole numbers become integer. If the field can hold 1.5, change it to number.
  • A null in the sample becomes type null. If the field is usually a string, use ["string", "null"].
  • An empty array gets no items schema, so its items are not checked.
  • Arrays with mixed items get an anyOf listing each distinct item schema.
  • No formats, patterns, enums or length limits are added; write those yourself.

What does required mean in JSON Schema?

The required keyword lists the property names an object must contain to be valid. It says nothing about their values, which the properties keyword describes. Without required, every property is optional: an object missing all of them still passes.

Understanding JSON Schema states that properties defined by the properties keyword are not required by default. It also explains that extra properties are allowed unless you set additionalProperties to false.

The generator lists every key from your sample as required, because it cannot tell which ones are optional. Remove the keys your data may omit. If you want to reject unknown keys, add additionalProperties yourself:

{
  "type": "object",
  "properties": {
    "id":   { "type": "integer" },
    "note": { "type": "string" }
  },
  "required": ["id"],
  "additionalProperties": false
}

Against this schema, {"id": 1} is valid, {"note": "x"} fails because id is missing, and {"id": 1, "extra": 2} fails because extra is not listed. Before building a schema, make sure the sample itself parses in the JSON validator.

Which JSON Schema draft should I use?

Use 2020-12, the current version on json-schema.org, unless the validator or platform you depend on supports only an older draft. The generator declares 2020-12 in its $schema line; the output uses only basic keywords, so it usually works with older drafts once you change that line.

The official specification page lists 2020-12 as the current release, superseding 2019-09, with migration notes for draft-07, draft-06 and draft-04. The specification is split into two documents: Core, which defines the foundation, and Validation, which defines the validation keywords.

How to choose:

  • Check which drafts your validator library supports, and pick the newest one it handles fully.
  • Keep the $schema line accurate, because validators use it to decide which rules apply.
  • If you use keywords whose meaning changed between drafts, follow the migration notes on json-schema.org before switching.

The JSON formatter is useful for tidying a schema after you edit it by hand.

Frequently asked questions

Can JSON have a schema?

JSON itself has no built-in schema, but JSON Schema is a vocabulary for describing JSON documents. A schema is itself a JSON document that lists the expected types, properties, required fields and constraints, and a validator checks data against it.

What is the difference between JSON and JSON Schema?

JSON is the data format. JSON Schema is a set of rules, written in JSON, that describes what valid data looks like, such as which fields must exist and what type each one has. You use the schema to validate, document or generate code for the data.

Is there an XSD equivalent for JSON?

JSON Schema plays that role. Like XSD for XML, it defines types, required fields, allowed values and nesting, and validator libraries check documents against it. It is written in JSON rather than XML, so the same tools that read your data can read the schema, and a generator like this one can draft it from a sample.

What is the JSON Schema format?

A JSON Schema is a JSON object whose keywords describe data: $schema names the draft, type sets the kind of value, properties and required describe objects, and items describes array contents. The current specification is 2020-12, published as Core and Validation documents.
