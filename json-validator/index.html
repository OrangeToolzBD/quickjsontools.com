JSON Validator

A JSON validator checks whether text follows the JSON grammar and, if not, tells you where it breaks. Paste your JSON and press Validate: you get either “Valid JSON” with a key count and minified size, or the line and column of the first error, judged against RFC 8259 (December 2017). Nothing leaves your browser.

Updated September 20, 2026 · By Quick JSON Tools

How do I check if JSON is valid?

Paste the text and press Validate. The tool runs the browser’s standard JSON parser over it. If parsing succeeds, the JSON is valid and the tool shows it formatted with 2-space indentation, plus a line such as “Valid JSON · 3 keys · 23 bytes minified”. If parsing fails, you get the first error with its position.

An error message looks like “Invalid JSON — line 1, column 8: Expected double-quoted property name in JSON at position 7”. That is the result for {"a":1,}: column 8 is the closing brace that follows the trailing comma. Fix that error and validate again, because a parser stops at the first problem and later errors only show up once earlier ones are gone.

This is a syntax check. It confirms the text is well-formed JSON, not that it has the fields your application expects. For that, you need a JSON Schema; the JSON Schema generator drafts one from a sample.

To check files in a script or CI job, both of these exit with an error when the file is invalid:

python -m json.tool data.json > /dev/null
node -e "JSON.parse(require('fs').readFileSync('data.json','utf8'))"

For the trailing-comma file above, Python 3.13 prints “Illegal trailing comma before end of object: line 1 column 7 (char 6)” and exits with status 1. Python points at the comma and the browser at the brace after it, so the two columns differ by one.

What are the most common JSON errors?

Most invalid JSON comes from writing it like JavaScript: trailing commas, single quotes, unquoted keys, comments, and values such as undefined or NaN. The rest are copy-paste accidents: a missing comma between items, an unclosed bracket, or a raw line break inside a string.

SymptomCauseFix
Error at a closing } or ]Trailing comma after the last itemDelete the comma
Error at the start of a keyMissing comma after the previous valueAdd the comma
Error at 'Single-quoted stringUse double quotes
Error at a letterUnquoted key, or True, None, undefinedQuote the key; use true, null
Error at a digitLeading zero such as 07Write 7, or store as a string
Error inside a stringRaw tab or line break, or a lone backslashEscape as \t, \n, \\
Error at the end of the textUnclosed bracket or stringCount brackets; close the string

RFC 8259 is specific about strings: quotation marks, backslashes and control characters from U+0000 to U+001F must be escaped. Windows paths are a frequent casualty, because each backslash needs doubling:

{"path": "C:\new\file.txt"}      invalid: \f is an escape, \n is a newline
{"path": "C:\\new\\file.txt"}    valid

The JSON stringify tool escapes a whole block of text for you.

JSON vs JSON5 and comments

Standard JSON has no comments. RFC 8259 does not allow them, and JSON.parse rejects them. JSON5 is a separate, looser format that adds comments, trailing commas, single quotes and unquoted keys. A JSON5 file is not valid JSON, so this validator will reject it.

The JSON5 project describes its format as a superset of JSON meant for files people edit by hand, such as configuration. Its additions include single-line and block comments, trailing commas, single-quoted strings, unquoted keys, hexadecimal numbers, Infinity and NaN.

Every valid JSON file is also valid JSON5, but not the other way round. So:

  • If a program reads the file with a strict JSON parser, remove the comments and other JSON5 features before shipping it.
  • If you need to annotate data, add a field such as "_comment": "..." that your code ignores.
  • If the file is only read by a tool that documents JSON5 or comment support, keep the comments, and validate it with that tool’s own parser rather than this one.

Some editors accept comments in certain JSON configuration files. That is a feature of those programs, not of JSON, and the same file may fail elsewhere.

Frequently asked questions

How do I validate JSON?

Paste it into the validator above and press Validate. Valid JSON is shown formatted, with a key count; invalid JSON gives the line and column of the first error. In code, call JSON.parse inside try and catch in JavaScript, or json.loads in Python, and treat an exception as invalid input.

How can I check if a JSON file is valid?

Open the file, copy its contents and paste them here, or check it from a terminal with python -m json.tool file.json, which prints an error and exits with status 1 if the file is invalid. The terminal route suits large files and automated checks, and the file never leaves your machine either way.

Is there an online validator for JSON format?

Yes, this page is one, and it checks syntax in your browser without uploading anything. Keep in mind that a syntax validator only proves the text is well-formed. To check that required fields exist and have the right types, validate against a JSON Schema with a schema validator.

What is the best tool to view JSON files?

For quick reading, a formatter or tree viewer is easiest. The JSON viewer shows nested data as collapsible branches, and the formatter indents it as text. Any code editor with JSON support also works and suits very large files, which can slow a browser page down.
