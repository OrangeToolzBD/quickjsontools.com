JSON Diff

A JSON diff compares two documents by their data, not their text. This one parses both sides and lists every value that was added, removed or changed, each with its path such as $.user.name. Key order and whitespace are ignored, so reformatting a file produces no differences. The comparison runs in your browser.

Updated September 20, 2026 · By Quick JSON Tools

How do I compare two JSON files?

Paste the original document on the left, the changed one on the right, and press Compare JSON. Both sides must be valid JSON. The result either says the documents are identical, with key order ignored, or gives a table of differences with the path, the kind of change and the values before and after.

Worked example from the tool’s tests:

Original: {"x": 1, "y": [1, 2], "z": {"k": "v"}}
Changed:  {"x": 2, "y": [1, 2, 3], "w": true}
PathChangeBeforeAfter
$.xchanged12
$.y[2]added3
$.zremoved{"k":"v"}
$.waddedtrue

That is 4 differences: 1 changed, 2 added and 1 removed. A removed or added object is reported once at its own path, not once per key inside it.

Paths start at $ for the root, add .key for object members and [n] for array positions. A change of type counts as a change: 1 and "1" differ. Two numbers that parse to the same value are equal, so 1.0 and 1 match.

If a side will not parse, the tool says “Both sides must be valid JSON” with the parser’s message. Validate each document to find the line.

Why does a text diff show false differences for JSON?

A text diff compares lines, and JSON can express the same data with different lines. Changing indentation, minifying, or writing keys in another order changes every affected line while the data stays the same. A structural diff parses first and compares values, so those changes vanish.

RFC 8259 treats the whitespace between tokens as insignificant and notes that JSON libraries differ in whether they preserve the order of object members. Two programs can therefore serialize identical data differently, and a text diff will flag every line that moved.

A: {"id": 7, "tags": ["x"]}
B: {
     "tags": ["x"],
     "id": 7
   }

A line diff reports every line of these as changed. This tool reports that the documents are identical. Use the line diff checker when layout matters, for example when reviewing a hand-edited configuration file, and this tool when only the data matters, such as comparing two API responses.

How are arrays compared?

Arrays are compared position by position: item 0 with item 0, item 1 with item 1, and so on. Extra items at the end show as added or removed. The tool does not try to match items that moved, so inserting one item at the start makes every later item look changed.

For example, comparing [1, 2, 3] with [0, 1, 2, 3] gives 4 differences: $[0], $[1] and $[2] changed, and $[3] added. Order matters for JSON arrays, so this is a real difference, but it may be more noise than you want.

Ways to get a cleaner result when order does not matter to you:

  • Sort both arrays the same way before comparing, for example by an id field.
  • Convert arrays of records into objects keyed by id, so each record is compared with its partner.
  • Compare one record at a time when only a few changed.
// JavaScript: key records by id before diffing
const byId = arr => Object.fromEntries(arr.map(r => [r.id, r]));
const a = byId(original.items), b = byId(changed.items);

With records keyed by id, a moved record produces no difference, and an edited one shows only the fields that changed.

Frequently asked questions

Does key order matter in a JSON diff?

Not in this tool. Objects are compared key by key, so the same keys in a different order produce no differences. Array order does matter, because arrays are ordered lists in JSON, and each item is compared with the item in the same position.

Can I compare JSON that has comments?

No. Both sides are parsed as standard JSON, which does not allow comments or trailing commas, so such a file is rejected with the parser’s error. Remove the comments first, or use a line diff if you want to compare the files exactly as written.

Is my JSON uploaded when I compare?

No. Both documents are parsed and compared by JavaScript in your browser, and nothing is sent to a server or stored. You can confirm this in the Network tab of your browser’s developer tools while you press Compare JSON. Even so, replace tokens and personal data with placeholders before pasting.
