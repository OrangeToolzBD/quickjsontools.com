UUID Generator

A UUID generator creates 128-bit identifiers written as 36 characters, such as 018bcfe5-6800-7000-8000-000000000000. This one makes random version 4 or time-ordered version 7 UUIDs, as defined in RFC 9562 (2024), using your browser’s cryptographic random generator, 1 to 50 at a time.

Updated September 20, 2026 · By Quick JSON Tools

What is a UUID?

A UUID (Universally Unique IDentifier) is a 128-bit value used to label records, files, events and messages without a central counter. It is written as 32 hex digits in five groups, 8-4-4-4-12. RFC 9562 notes UUIDs are also known as GUIDs, and it replaced the older RFC 4122.

Two digits carry metadata. The first digit of the third group is the version: 4 for random, 7 for time-ordered. The first digit of the fourth group holds the variant, and for RFC UUIDs it is 8, 9, a or b.

xxxxxxxx-xxxx-Vxxx-Nxxx-xxxxxxxxxxxx
               ^    ^
          version   variant (8, 9, a or b)

Paste a UUID and press Check UUID to read these: the tool reports whether the value has the 8-4-4-4-12 hex shape, its version, and whether the variant is the RFC 9562 one. The specification also defines two special values: the Nil UUID, all zeros, and the Max UUID, all ones (all f).

The generator outputs lowercase by default, with an option for uppercase. RFC 9562 allows either case when a UUID is read, so compare UUIDs case-insensitively.

UUID v4 vs v7: which should I use?

Use v7 when UUIDs serve as database keys or need to sort by creation time; use v4 when the ID should reveal nothing. A v4 UUID is 122 random bits. A v7 UUID starts with a 48-bit Unix timestamp in milliseconds, followed by random bits, so values created later sort later.

RFC 9562 says implementations should use v7 instead of v1 and v6 where possible, and explains that time-ordered values improve database index locality because new values sit near each other in the index.

The tool’s test shows the layout. With the time set to 1700000000000 ms and the random bits set to zero, v7 gives:

018bcfe5-6800-7000-8000-000000000000

The first 12 hex digits, 018bcfe56800, are 1700000000000 in hexadecimal: November 14, 2023, 22:13:20 UTC, which you can check in the Unix timestamp converter. That is the trade-off: anyone holding a v7 UUID can read when it was made, which the RFC describes as a very small attack surface.

One limit of this generator: within a single millisecond, v7 values here are purely random after the timestamp, with no counter. RFC 9562 makes such a counter optional. If you generate 50 at once, they share a timestamp but are not guaranteed to sort in creation order. If strict ordering matters, use a library that implements the RFC’s monotonic method.

Can two UUIDs collide?

In principle yes, in practice almost never, if the random bits come from a good generator. A v4 UUID has 2¹²² possible values, about 5.3 × 10³⁶. You would need around 2.7 × 10¹⁸ random v4 UUIDs for a 50% chance of a single duplicate.

Those figures come from the standard birthday-problem approximation, computed for this page. For a billion v4 UUIDs, the chance of any duplicate is about 1 in 10¹⁹. For v7, only UUIDs created in the same millisecond can collide; with 74 random bits, a 50% chance needs about 1.6 × 10¹¹ of them in that one millisecond.

Real collisions come from bad randomness, not from the math: a weak random function, a cloned virtual machine or a copied value. This tool uses crypto.getRandomValues, which MDN (updated August 19, 2025) describes as producing cryptographically strong random values.

Do not treat a UUID as a secret. RFC 9562 says implementations should not assume UUIDs are hard to guess and must not use them as security capabilities, identifiers that grant access just by being known. Use a proper random token for that. To store a hash of an identifier instead, see the hash generator.

Frequently asked questions

How do I generate a UUID?

Choose v4 or v7 and how many you need, then press Generate. In code, modern browsers and Node.js offer crypto.randomUUID() for v4, and Python has uuid.uuid4(). For v7, use a library that follows RFC 9562, and generate IDs where they are created rather than copying them.

What does UUID mean?

UUID stands for Universally Unique IDentifier: a 128-bit label written as 36 characters, designed so that separate systems can create IDs independently without clashing. RFC 9562 notes that UUIDs are also known as GUIDs, Globally Unique IDentifiers, so the two names describe the same format.

What can an attacker do with a UUID?

Usually nothing by itself, as long as your application checks permissions. The risk comes when a UUID is the only thing protecting a resource, such as a share link, since RFC 9562 warns UUIDs should not be assumed hard to guess. A v7 UUID also reveals its creation time.

Is a UUID truly unique?

Uniqueness is not guaranteed, but random UUIDs are unique for all practical purposes when generated with a cryptographic random source. Most real duplicates come from software bugs, weak random functions or copied data, so keep a unique constraint in your database anyway and let it catch the rare mistake.
