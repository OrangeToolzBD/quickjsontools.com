Regex Tester

A regex tester runs your regular expression against sample text and lists every match with its position and capture groups. This one uses JavaScript’s regex engine, as described in MDN’s regular expressions guide (updated March 17, 2026), and stops any pattern still running after 2 seconds so a runaway pattern cannot freeze the page.

Updated September 20, 2026 · By Quick JSON Tools

How do I test a regular expression?

Type the pattern without the surrounding slashes, enter flags such as g or gi, paste your test text and press Test. The tool lists up to 200 matches in a table: the match number, the index where it starts, the matched text and each capture group in order. It counts up to 1,000 matches in total.

Worked example from the test suite: the pattern (\w+)@(\w+)\.com with flag g against a@b.com, c@d.com finds 2 matches. The first starts at index 0 with groups a and b; the second starts at index 9 with groups c and d. A group that did not take part in a match shows as ∅.

Some details of how the tool behaves:

  • Without the g flag, only the first match is shown, just as RegExp.prototype.exec returns one match.
  • Patterns that can match an empty string, such as \b, do not loop forever: after an empty match the tool steps forward one character. \b on hi there reports 4 zero-length matches, at indexes 0, 2, 3 and 8.
  • A syntax error comes back as the engine’s message; an unclosed ( gives “Invalid regular expression: /(/g: Unterminated group” in Chrome.
  • Named groups such as (?<user>\w+) work; their values appear in the Groups column in order.

Type the pattern exactly as you would inside a regex literal. In a JavaScript string passed to new RegExp(), every backslash has to be doubled:

const a = /\d{4}-\d{2}/g;              // literal
const b = new RegExp("\\d{4}-\\d{2}", "g"); // same pattern in a string

Your pattern and text stay in the browser; the tester does not upload them.

What do the regex flags g, i, m, s, u and y do?

Flags change how the whole pattern is applied. g finds every match instead of the first, i ignores case, m makes ^ and $ match at line breaks, s lets the dot match newlines, u treats the pattern as Unicode code points, and y matches only at the current position.

FlagNameEffect
gglobalFind all matches, not just the first
iignore case/abc/i matches ABC
mmultiline^ and $ match at the start and end of each line
sdotAll. also matches line breaks
uunicodeCode-point matching; enables \p{...} property escapes
ystickyMatch only at lastIndex, never further along
dindicesRecord start and end positions of groups
vunicodeSetsAn upgraded u mode with more Unicode features

The table follows MDN’s flag list. The flags field accepts any of them; an unknown letter such as x is rejected by the engine with “Invalid flags supplied to RegExp constructor”. For example, ^\w+ with flags gm on the two lines “one two” and “three four” matches “one” at index 0 and “three” at index 8. Without m, only “one” matches.

The sticky flag trips people up. MDN’s lastIndex page (updated July 20, 2025) explains that with y the engine tries only at the exact position in lastIndex and does not search ahead, which suits tokenizers but surprises anyone expecting a normal search.

Why is my regex so slow?

Most slow regexes suffer from catastrophic backtracking: nested or overlapping quantifiers give the engine an exponential number of ways to try, and fail, a match. The classic shape is a repeated group that itself repeats, such as (a+)+$, run against a long string that almost matches.

The OWASP page on regular expression denial of service works through ^(a+)+$: an input of four a’s and a non-matching character has 16 possible paths, 16 a’s give 65,536, and each extra a doubles the count. The same page lists other risky forms, including ([a-zA-Z]+)*$, (a|aa)+$ and (a|a?)+$.

This tester runs your pattern in a Web Worker, a background thread separate from the page. If no answer arrives within 2 seconds, it stops the worker and says the pattern is too slow on this text. That protects the tab, but treat the warning as a bug report: the same pattern will hang a server too.

Ways to fix it:

  • Remove nested quantifiers: (a+)+ matches the same strings as a+.
  • Make alternatives mutually exclusive, so only one branch can match a given character.
  • Anchor the pattern and use specific classes such as [^,]* instead of .*.
  • Limit input length before matching untrusted text.
  • In Java, and in Python 3.11 or later, possessive quantifiers and atomic groups stop backtracking. JavaScript does not support them.
// slow on "aaaaaaaaaaaaaaaaaaaaaaaaaaaa!"
/^(a+)+$/
// same matches, no nested repetition
/^a+$/

How does JavaScript regex differ from Python and Java?

The core syntax is shared, but the three engines differ in named-group syntax, how flags are set, how you find all matches, and which backtracking controls exist. Test here for JavaScript; for Python or Java, check the points below before copying a pattern across.

Sources: the Python re documentation and the Java SE 21 Pattern reference. Python’s docs note that lookbehind must be fixed-width. In Java, an unescaped "\b" in a string literal is a backspace character, not a word boundary, so write "\\b". Python’s re.match only matches at the start of the string, while re.search looks anywhere, which is what a JavaScript regex does by default.

# Python
import re
re.findall(r"(\w+)@(\w+)\.com", "a@b.com, c@d.com")  # [('a', 'b'), ('c', 'd')]

Frequently asked questions

Which regex flavor does this tester use?

It uses the JavaScript (ECMAScript) engine built into your browser, so results match what the same pattern does in JavaScript code running in that browser. Most simple patterns behave the same in Python and Java, but named groups, flags and backtracking controls differ, as the comparison table above shows.

Why does my regex find only one match?

The g flag is missing. Without it, a JavaScript regex stops after the first match, and this tester does the same. Add g to the flags field to list every match. In Python, use re.findall or re.finditer instead, because Python has no g flag.

Is my test text sent anywhere?

No. The pattern and text are handed to a Web Worker created inside your own browser tab, and the result comes back to the page. Nothing is uploaded or stored; the methodology page explains what runs where. Even so, use sample data rather than real logs that contain tokens or personal information.
