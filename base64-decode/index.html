Base64 Decode and Encode

To Base64 decode, map each character back to its 6-bit value and regroup the bits into bytes: every 4 characters give 3 bytes. RFC 4648 (October 2006) defines the 64-character alphabet and the = padding. Paste Base64 and press Decode to read it as UTF-8 text, or Encode to go the other way, locally.

Updated September 20, 2026 · By Quick JSON Tools

How do I decode Base64?

Paste the Base64 string and press Decode. The tool trims spaces and line breaks, accepts the URL-safe characters - and _, adds any missing = padding, decodes the bytes and reads them as UTF-8 text. Invalid input, or bytes that are not UTF-8 text, produce an error instead of garbled output.

Worked examples from the tool’s tests:

Base64Decoded text
aMOpbGxvIHfDtnJsZCDinJM=héllo wörld ✓
aGk_Pz8 (URL-safe, no padding)hi???

The first shows why UTF-8 handling matters: é, ö and ✓ each take two or three bytes. MDN notes (updated June 24, 2025) that the browser’s atob returns one character per byte, so decoding without a UTF-8 step turns those letters into symbols. This tool adds that step.

The error “This is not valid Base64, or it decodes to bytes that are not UTF-8 text” means one of two things: the input contains characters outside the alphabet, or it encodes binary data such as an image or a ZIP file. This tool shows text only; it does not save decoded files.

// JavaScript (UTF-8 safe)
const text = new TextDecoder().decode(Uint8Array.from(atob(b64), c => c.charCodeAt(0)));

# Python
import base64
text = base64.b64decode(b64).decode("utf-8")

# Linux shell
echo 'aGVsbG8=' | base64 -d

What is Base64 used for?

Base64 carries binary data through channels that only handle text. It shows up in email attachments, data: URLs, JSON and XML fields that hold files or keys, the HTTP Basic authentication header, and the parts of a JSON Web Token. The cost is size: every 3 bytes become 4 characters, about a third larger.

The encoding takes 3 bytes (24 bits) at a time, splits them into four 6-bit groups, and writes each group as one of 64 characters: A–Z, a–z, 0–9, + and /. When the input does not divide evenly by 3, = signs pad the output to a multiple of 4. RFC 4648’s test vectors show this:

InputBase64
fZg==
fooZm9v
foobarZm9vYmFy

To encode, paste text and press Encode; hello gives aGVsbG8=. Text is converted to UTF-8 bytes first, so any language works. JWTs use the URL-safe variant; to read one, the JWT decoder splits and decodes all its parts at once.

What is URL-safe Base64?

URL-safe Base64, called base64url in RFC 4648, swaps the two characters that clash with URLs and file names: - replaces + and _ replaces /. The padding = is often left off, because RFC 4648 lets a referring specification drop it. JWTs are a common example.

For example, hi??? encodes to aGk/Pz8= in standard Base64 and aGk_Pz8 in URL-safe form. In a URL, the / would be read as a path separator and the + could become a space, and = has meaning in query strings too.

This tool decodes both forms automatically. Its encoder produces standard Base64; convert the result like this:

const urlSafe = b64.replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");

If you only need to place a standard Base64 string in a query parameter, percent-encoding it with the URL encoder also works.

Is Base64 encryption?

No. Base64 is an encoding with no key: anyone can reverse it, instantly, with any tool. RFC 4648 says it can visually hide information such as passwords but “does not provide any computational confidentiality.” Treat Base64 text as plain text.

This matters in practice. An HTTP Basic authentication header is only a Base64 copy of the user name and password, so it must travel over HTTPS. A secret or configuration value stored as Base64 is readable by anyone who can see the file. And a JWT payload, though it looks scrambled, is readable by anyone holding the token.

Do not paste real credentials or tokens into any online decoder, including this one. Decoding here happens in your browser and nothing is uploaded, but copied secrets can still leak through clipboard history, screenshots or browser extensions. If data needs protecting, encrypt it with a real cipher, then Base64-encode the ciphertext if it must travel as text.

Frequently asked questions

Why does Base64 end with = or ==?

The equals signs are padding. Base64 works in groups of 3 bytes, and when the input length is not a multiple of 3, one or two = characters fill out the last 4-character group. One leftover byte gives ==, two give =. Some formats drop the padding; this decoder adds it back.

Can I decode a Base64 image here?

No. This tool decodes Base64 to text and reports an error when the bytes are not valid UTF-8, which is the case for images and other binary files. To view a Base64 image, put it in a data: URL in an img tag, or decode it with a script and save the bytes to a file.

Is my data uploaded when I decode?

No. Encoding and decoding run in JavaScript in your browser, with no network request and no storage, so the text you paste never reaches a server. You can confirm it in your browser’s developer tools on the Network tab. Still, avoid pasting live credentials: Base64 hides nothing, and copied text can linger in clipboard history.
