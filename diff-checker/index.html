Diff Checker

A diff checker compares two versions of a text and marks every line that was added or removed. Paste the original on the left and the changed version on the right, then press Compare. The comparison runs in your browser with a longest-common-subsequence line diff, so private files are never uploaded.

Updated September 20, 2026 · By Quick JSON Tools

How do I compare two text files?

Open both files, paste the original into “Original text” and the new version into “Changed text”, then press Compare. The result starts with a count of added and removed lines, followed by the merged listing: unchanged lines, lines only in the original (marked with a minus) and lines only in the new version (marked with a plus).

Each marked line carries its line number from its own file, so -2 means line 2 of the original and +2 means line 2 of the changed text. The tool’s test case compares three short lines:

OriginalChangedResult
aaunchanged (line 1)
bB-2 b then +2 B
ccunchanged (line 3)

The summary reads 1 line added and 1 line removed. A diff checker sees an edited line as one removal plus one addition; it does not highlight the changed characters within the line.

Comparison is exact. Trailing spaces, tabs versus spaces and a different letter case all count as changes, even though they look the same on screen. If a line you expected to match is flagged, turn on visible whitespace in your editor, or trim trailing spaces from both versions before pasting.

Very large inputs are refused rather than frozen: if the line count of one side times the other exceeds 25 million (5,000 lines against 5,000, for example), the tool asks you to split the text.

How does a line diff work?

A line diff finds the longest sequence of lines that appears, in order, in both texts. Those lines are unchanged. Everything in the original that is not part of that sequence was removed, and everything in the new text that is not part of it was added.

This tool builds a table of longest-common-subsequence lengths for every pair of line positions, then walks it from the top to produce the output. When two outcomes are equally short, it lists the removal before the addition, which is why an edited line appears as a minus line followed by a plus line.

Command-line tools use faster algorithms that trade a little precision for speed on large files. The GNU diff manual (Diffutils 3.12, January 2025) says its method finds a “near-minimal set of differences”, and it offers a --minimal option when you need the smallest possible set. For pasted text, the exact method used here is fast enough and always minimal in line count.

For comparison on the command line:

diff -u original.txt changed.txt
git diff --no-index original.txt changed.txt

Both print a unified diff, the same plus and minus notation used above, with a few lines of context around each change.

How do I compare two JSON files?

For JSON, a line diff works only if both files are formatted the same way. Format both sides with the same indentation first, or use a structural comparison that ignores formatting and key order. Otherwise a reordered object or a minified file shows as a wall of changes even when the data is identical.

The quickest route is to run each file through the JSON formatter with 2-space indentation, then paste both results here. That gives a readable line diff.

The JSON diff tool goes further. It parses both documents and compares values by path, so {"a":1,"b":2} and {"b":2,"a":1} count as identical, and a changed value is reported once, with its path, instead of as a removed and an added line.

Frequently asked questions

Is this diff checker safe for private files?

Yes, in the sense that the comparison happens entirely in your browser. The page sends nothing you paste to any server and stores nothing, which you can check in the Network tab of your developer tools. Still avoid pasting live credentials or personal data into any web page, since extensions and clipboard history can expose them.

Where can I find a diff checker online?

This page is one: paste two texts and press Compare. If you already use Git, you do not need a browser at all; the command git diff --no-index file1 file2 compares any two files on disk, and most code editors have a built-in compare view.

How do I choose the right diff checker?

Match the tool to the data. For plain text and code, a line diff is standard. For JSON, prefer a structural diff that ignores key order, such as the JSON diff. For confidential material, choose a tool that runs locally and that you can verify makes no network requests while you compare.
