JSON to YAML and XML Converter

To convert JSON to YAML, paste JSON and press JSON → YAML: objects become indented key: value lines and arrays become dash lists. The same box converts JSON to XML and YAML back to JSON. Since YAML 1.2 is a superset of JSON, the data carries over unchanged. Everything runs in your browser.

Updated September 20, 2026 · By Quick JSON Tools

How do I convert JSON to YAML?

Paste valid JSON and press JSON → YAML. The tool writes 2-space indented YAML: each object key on its own line, arrays as lines starting with a dash, and empty arrays and objects as [] and {}. To go the other way, paste YAML and press YAML → JSON.

Worked example from the tool’s tests:

{"a": 1, "b": [1, "x"], "c": {"d": null}, "e": "true"}

a: 1
b:
  - 1
  - x
c:
  d: null
e: "true"

Notice that the string “true” is quoted in the YAML. Without quotes, a YAML parser would read it as the boolean true. The converter quotes any string that could be mistaken for another type (true, false, null, yes, no or a number) and any string with characters beyond letters, digits, spaces and . / @ - _ . Quoted strings use JSON’s double-quote syntax, which YAML also accepts.

Keys are written as they are, so a key containing a colon followed by a space, or a space followed by #, needs quotes added by hand. An array of objects is written with each dash on its own line and the object’s keys indented beneath it. That is valid YAML, although many people write the first key on the dash line.

YAML → JSON uses the MIT-licensed js-yaml parser, and errors are reported by it. For a syntax check with line numbers, use the YAML validator. This tool does not convert XML back to JSON.

How does JSON map to XML?

Each JSON key becomes an element with the same name, and its value becomes the element’s content. Nested objects become nested elements, and each array item becomes a repeated element named after the array’s key. If the JSON object has exactly one top-level key, that key is the root element; otherwise everything is wrapped in <root>.

{"item": [1, 2], "name": "x"}

<root>
  <item>1</item>
  <item>2</item>
  <name>x</name>
</root>

That is the tool’s test case: two top-level keys, so a root element was added, and the array became two item elements. Some mapping rules to know:

  • null becomes an empty element such as <name/>.
  • &, < and > in values are escaped as entities.
  • Characters not allowed in a name, such as spaces, become underscores: “first name” becomes first_name.
  • Everything becomes element text. Types are lost, so 1, "1" and true all come back as text, and no attributes are produced.
  • A key that starts with a digit gives an element name XML does not allow; rename such keys first.
  • A top-level array produces several root elements, which is not well-formed XML; wrap it in an object with one key.

The XML 1.0 specification (Fifth Edition, November 26, 2008) requires exactly one root element. To tidy or check the result, paste it into the XML formatter.

When should I use YAML instead of JSON?

Use YAML for files people write and review by hand, such as configuration, where comments and a lighter syntax help. Use JSON for data exchanged between programs and APIs, where a small, strict grammar and universal parser support matter more. Many tools accept both.

The YAML 1.2.2 specification (October 1, 2021) describes YAML 1.2 as a strict superset of JSON, so any valid JSON document is also YAML. The differences cut both ways:

JSONYAML
CommentsNot allowed# comments
StructureBrackets and bracesIndentation (spaces only)
String quotesAlways requiredUsually optional
Implicit typingNoneUnquoted values may become numbers, booleans or null
Multiple documents per fileNoYes, separated by ---

YAML’s flexibility is also its risk. Indentation errors change the structure silently, and unquoted values can be typed in ways you did not intend, as 007 turning into the number 7 shows. If a YAML file is generated by a program, converting from JSON as this tool does and quoting ambiguous strings is a safe pattern.

Frequently asked questions

Is every JSON file valid YAML?

Under YAML 1.2, yes: the specification describes YAML 1.2 as a strict superset of JSON, so a YAML 1.2 parser can read JSON directly. Older YAML 1.1 parsers may differ on details. Converting to block-style YAML is about readability and room for comments, not compatibility.

Why is a value quoted in my YAML output?

The converter quotes strings that a YAML parser could read as something else, such as "true", "null", "yes" or "42", and strings with punctuation beyond a few safe characters. Quoting keeps them strings when the YAML is read back, so the round trip returns exactly the JSON you started with.

Can this tool convert XML to JSON?

No. It converts JSON to YAML, JSON to XML and YAML to JSON. XML has attributes, mixed content and repeated elements that have no single JSON equivalent, so XML to JSON needs mapping choices this tool does not make. A script using your language’s XML parser gives you control over those choices.
