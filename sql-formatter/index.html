SQL Formatter

A SQL formatter rewrites a query with each clause on its own line and consistent indentation, and can uppercase keywords. This one uses the MIT-licensed sql-formatter library with dialects for standard SQL, PostgreSQL, MySQL, SQL Server, SQLite and BigQuery, running in your browser.

Updated September 20, 2026 · By Quick JSON Tools

How do I format a SQL query?

Paste the query, pick the dialect your database uses, choose whether to uppercase keywords, and press Format SQL. The library breaks the statement into clauses such as SELECT, FROM, WHERE and ORDER BY, puts each on its own line, and indents the columns and conditions under them. Copy the result back into your editor.

A typical one-line query to try, from the tool’s placeholder:

select id, name from users where active = 1 order by name

With “Uppercase keywords” ticked, the keywords come back as SELECT, FROM, WHERE and ORDER BY on separate lines, with the column list indented beneath SELECT. Untick it to keep your original keyword case.

Why the dialect matters: databases disagree on quoting and syntax. MySQL quotes identifiers with backticks, SQL Server uses square brackets, and PostgreSQL has operators such as :: for casts. Picking the matching dialect helps the formatter read those correctly instead of splitting them in odd places.

The sql-formatter project states that it formats whitespace and does not validate SQL, and that it does not support stored procedures. It is also in maintenance mode, with bug fixes but no new features planned. If a procedure body comes out oddly, format the individual statements instead.

If the page shows that the formatter library is not loaded, the page is missing its vendored copy of the library; nothing is fetched from elsewhere.

Should SQL keywords be uppercase?

It is a readability convention, not a rule. SQL keywords are case-insensitive, so select and SELECT run the same. Many teams uppercase keywords and lowercase table and column names so the query’s structure stands out. Whatever you choose, apply it consistently.

The PostgreSQL 18 documentation states that key words and unquoted identifiers are case-insensitive, and mentions the convention of writing key words in upper case and names in lower case.

UPDATE my_table SET a = 5;   -- convention
update MY_TABLE set A = 5;   -- same statement

Identifiers are different when quoted. In PostgreSQL, unquoted FOO and foo are the same name, but "Foo" in double quotes is a different one. That is why a formatter should change keyword case only and leave identifiers alone, which is what the “Uppercase keywords” option does. With it unticked, the formatter keeps your keyword case as written.

Does formatting change what a query does?

It should not. Formatting changes spaces, line breaks and optionally keyword case, and SQL ignores all three outside string literals and quoted identifiers. Still, compare before and after for anything important, because a formatter that misreads unusual syntax can move text in ways that matter.

Things worth checking after formatting:

  • String literals are unchanged, including any spaces or line breaks inside them.
  • Quoted identifiers kept their exact case.
  • Comments stayed with the line they describe; a -- comment that ends up in front of code would comment that code out.
  • Vendor-specific syntax, such as MySQL’s DELIMITER lines, did not get split.

A quick way to check: paste the original and the formatted query into the diff checker, or run both with EXPLAIN and compare the plans. Your SQL is processed in the browser, so table names and literal values in the query are not uploaded. The methodology page lists the library version the page expects.

Frequently asked questions

What is a SQL formatter?

A SQL formatter is a tool that re-lays out SQL code with consistent line breaks, indentation and keyword case, so long queries are easier to read and review. It does not check that the query is correct or run it.

How can I beautify MySQL code?

Paste the query above, choose MySQL as the dialect and press Format SQL. Choosing MySQL lets the formatter recognize backtick-quoted names and other MySQL syntax. For many files, run the same sql-formatter library from the command line or a build script.

Is it safe to paste production queries?

The query is formatted in your browser and not sent anywhere, so the text stays on your machine. Queries can still contain sensitive values, such as email addresses, account numbers or keys in WHERE clauses, so replace those with placeholders before pasting into any web page, including this one.
